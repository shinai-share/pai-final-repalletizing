# 構成と設計の考え方

## 何を作ったか

輸送中に荷崩れしたパレット（48 ケース）を、門型の吸着ロボットが別のパレットへ正しい姿勢に戻して積み替える作業を、NVIDIA Isaac Sim の物理シミュレーションの中で自律的に行う。
1 個を「移載済み」と数えるのは、B の決められた区画に（10 mm 以内）、正しい姿勢で（向き・傾き 2 度以内）置かれ、手を離して 3 秒たっても動かないことを、ロボット自身のカメラで確かめたときだけである。
人が与えるのは「パレット A の荷を B へ積み替えて」という目的だけである。どこから見るか、どのケースから取るか、取った後に何を確かめるかは、ロボットが自分の「見立て」から決める。

中心にある考え方は一つである。

**自分がまだ何を知らないかを数えて持ち、その不確かさが次の判断を変えうるときだけ、見に行く。**

## 層の分け方

```
目的（人）
  │
司令塔 executive.py ── 方式: shinai / observe_all / top_first
  │   ├ 見立て pile.py（支え・連鎖落下・未観測・吸着できるか）
  │   ├ 認識 perception/（距離画像→点群→既知空間の地図→箱の当てはめ）
  │   ├ 観測計画 viewplan.py（どこを見れば判断が確定するか）
  │   └ 安全監督 safety.py（AI から独立。周期ごとに点検）
  │
窓口 backend.py ── 司令塔が頼めることは「動かす・撮る・吸着する」だけ
  │
  ├ Isaac Sim  sim/isaac_backend.py, sim/runtime.py, sim/cell.py
  └ 模擬       fake_backend.py（解析的な描画と単純な落下規則。試験専用）

評価 evaluation/（真値と比べる。司令塔からは読めない）
Inspector inspector_server.py + ui/（記録を読むだけ）
```

司令塔・見立て・認識・観測計画・安全監督は、シミュレーターも真値も読み込まない。これは試験 `test_cognitive_core_never_imports_ground_truth` が構文木で確かめる。

## 見立て（Belief）が持つもの

| 持つもの | 中身 |
|---|---|
| ケースの姿勢 | 位置・向き・寸法の割り当て・確からしさ（上面が見えた割合と、位置が決まらなかった分から） |
| 支え | 上向きの面に乗る「下からの支え」と、横の面に触れる「寄りかかり」を分ける。重心が支えの外に出て、倒れる側に横の接触があるときだけ寄りかかりを支えと数える |
| 連鎖落下の予測 | ケースを抜いたとき、支えを失うケースを順にたどる。落ちる高さで重みを付ける（数 cm 傾くだけのものは崩れと数えない） |
| 説明できない支え | 観測した山は静止している。幾何の上で支えが足りないケースは「見えない支えがある」とみなし、確実な連鎖としては広げない。触れている候補の危険度にだけ半分の重みで加える |
| 見えていない空間 | 光線が通った格子（空き）・止まった格子（何かある）・届いていない格子（未観測）。未観測のうち、どのケースでも説明されず、下に空きがない（宙に浮かない）ものだけが、ケースが隠れうる場所 |
| 中身の偏り | 重心を「箱の中心 ±60 mm」の幅で持つ（商品の知識）。幅の全体が支えの上なら安定、一部がはみ出せば不確かとし、不確かな落下は半分の重みで危険度に入れる |
| 吸着できるか | 上面の傾き 50° 以内（吸着パッドの倣い 15° と手首のピッチ 35°）、上面が半分以上見えている、確からしい隣の推定と重ならない、面の法線方向に障害がない、届く範囲にある |

## 判断の順序（方式 shinai）

1. 安全な候補（危険度 0.25 以下）があれば、いちばん高いものから取る。
2. なければ、判断を変えうる不確かさがあるかを見る。あれば、その不確かさを最も解消できる視点を、移動時間で割った価値で選び、見に行く（1 つの判断につき 3 回まで）。
3. 見ても決まらなければ、危険度 0.6 以下の最も安全な候補を取る（代替の取り出し）。
4. それもなければ、人の確認を求めて止まる。

取ってから置くまでは次のとおり。

1. 面に直角に近づいて触れ、3 mm 戻してから吸う。傾いた面には手首を合わせる。
2. 4 cm 持ち上げて止まり、手首の力とトルクから質量と重心を量る（試し持ち上げ）。
3. 床のカメラで下から測る。高さで姿勢（正立・横倒し・立ち）が分かり、下面の平面から持ち方の傾きと吸着のずれが分かる。下面が一部しか見えなければ、測れなかったとする。
4. 吸着が中心から 40 mm 以上ずれていれば、姿勢復元台に置いて中心で持ち直す。横倒し・立ちなら、吸着面の長辺まわりに 90 度起こして台に立て、垂れをカメラで見て取り返し、天面で持ち直す。起こすとはがれモーメントが吸着の 1/3 を超えるなら、起こさず人に渡す。
5. B の区画が空いていることをカメラで確かめてから、ケースの重さが吸着から抜けるまで 0.05 m/s で下ろして離す。
6. ケース自身の上面で位置・向き・傾きを測り、3 秒後にもう一度測る。外れていれば上面で掴み直して置き直す（1 回まで）。

## 学習：自分の見立てがどこで外れるかを、物理から学ぶ

連鎖落下の予測は、まず幾何の規則（支えと重心）で行う。これに加えて、その規則がどこで外れるかを学習する部品を持つ（`shinai_pi/learning/cascade.py`）。

1. Isaac Sim で荷崩れの山を作る。山ごとに輸送の条件と摩擦（0.35〜0.65）を、ケースごとに重さ（8〜14 kg）と重心（水平 ±60 mm）を乱数で振る（ドメインランダム化。v2）。
2. ケースを 1 個取り除いて 1.5 秒進め、周りのどれが実際に動いたかを記録する。山は毎回元に戻す。半分は何かを支えているケースから選ぶ。
3. 特徴量は、真値に認識の誤差相当の雑音（位置 1 cm・向き 1.5°）を加えた姿勢から、見立てと同じ計算で取り出す。
4. ロジスティック回帰を学習し、見ていない山（別の乱数の種）で幾何の規則と比べる。確率は「何個動く見込みか」に使うので、校正を保つ。
5. 予測器は JSON（重みだけ）で保存し、設定で指定したときだけ見立てに差し込む。

## 物理シミュレーションの作り

- 門型ガントリー（x・y・z・旋回）と手首 2 軸（ロール ±110°・ピッチ ±35°、回転の中心は吸着面の中心）、吸着パッド 4 個（Isaac Surface Gripper、1 個 300 N）。昇降柱は吸着面から 0.24 m 上で終わる（起こすケースが当たらない）。
- 手首の力覚は、吸着ヘッドへの関節反力。Isaac の値は荷重の約 1/8 でトルクの符号が逆のため、重さと重心が既知のケースで校正した（`scripts/probe_wrist.py`）。
- ケースごとに質量と重心を変え、慣性も重心に合わせて設定する。真値は評価にだけ使う。
- 姿勢復元台（0.24 m 角・高さ 0.12 m）を B の脇に 2 台。ケースより小さいので、横に付いた吸着板が台に当たらない。
- 人が見るための視点が 3 つある（全景・横から・手元）。ロボットの判断には使わない。
- パレット A・B は JIS T11（1,100 mm）、間は 0.8 m。
- 荷崩れは、荷台と一緒に動く座標系での加速度（急ブレーキ・横揺れ・段差）を、見かけの重力の時間変化として与えて起こす（等価原理）。ストレッチフィルムが切れた上段だけが動く。条件は seed で再現できる。
- 置くときの着地は吸着ヘッドの力（ケースの重さが抜けたことが続いたら）で、吸着前の接触は上下軸の駆動力で検知する。

## 正直に書いておくこと

- 物体の切り分け（どの画素がどのケースか）は、シミュレーターの分割を使っている。姿勢・支え・見えないケースは、すべて距離画像から推定している。分割の学習モデルへの置き換えは次の段階である。
- 吸着はシミュレーターの近似である。実機の吸着力・漏れは測っていない。吸着パッドの倣い（剛性 10,000）は、回す途中で外れない値を実測で選んだ（`scripts/probe_turn.py`）。
- 接触の瞬間の押し付け力には、剛な位置制御の模型に由来する山がある。
- 光線式安全装置は、人の模型の位置で模擬している。認証された安全機能ではない。
- 結果はシミュレーションの中での性能であり、実機での性能を主張しない。
