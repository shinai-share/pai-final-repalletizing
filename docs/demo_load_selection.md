# 短い実演の荷の選び方（2026-11-01 夜、測定の前に固定）

目的：全工程を省略せずに、2 倍速で 3 分以内の動画に収める。
これまでの 1 箱あたりの時間（約 48 秒）から、6 箱の荷にする。

## 荷

| 項目 | 値 |
|---|---|
| 箱の並び | 横 3 × 奥 1 × 2 段＝6 箱（段は回さない。上の箱は下の箱に載る）。`run_mission.py --grid 3 1 2` |
| 品目 | BEV-500x24 |
| 輸送 | 番号ごとの既定の輸送（`shinai_pi/transport.py`、これまでの走行と同じ範囲） |
| 機体と判断 | 2026-10-31 の作り直しの版。崩れの予測は、真上のカメラの見立てから学んだ予測（`shinai_learned`、`models/cascade_v4_camera.json`） |

## 開始状態の条件

[start_state_selection.md](start_state_selection.md) と同じ 4 条件で判定する（上の段は 3 箱）。

1. 「床」と「段から落ちた」が 0 個
2. 上の段の半数以上（2 箱以上）が「ずれた」か「傾いた」
3. 上の段の水平の移動の最大が 0.10 m 以上
4. 上の段の水平の移動の中央値が 0.04 m 以上

## 試す番号と使い方

- 番号 200 から 239 までを順に、荷崩れだけを物理計算して判定する（`scripts/survey_start_shift.py --grid 3 1 2`）。ロボットは動かさない。
- 最初に 4 条件を満たした番号で、1 回だけ走らせる。走行の結果で番号を選び直さない。
- 判定は段階 S3（`scripts/stage_gate.py`、基準は変えない）。不合格なら不合格として記録する。
- 239 までに満たす番号がなければ、その事実を残し、条件も範囲も広げない。

判断を規則から、カメラの見立てから学んだ予測に変えた。課題が AI の利用を求めているためである。
