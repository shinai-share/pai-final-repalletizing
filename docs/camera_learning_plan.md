# 内蔵カメラの見立てから学ぶ崩れの予測（2026-11-01、データを作る前に固定）

目的：学習の入力を、ロボットが内蔵カメラから作る見立てにそろえる（2026-11-01 の方針：カメラ由来の学習を本来の目的として続ける）。
これまでの予測（cascade_v3）は、シミュレーターの正しい位置に雑音を足したものを入力にしていた（`docs/generalisation_plan.md` の追記）。

この文書は、データを作る前に書いた。結果を見た後に、条件・基準・番号を変えない。

## 変えること・変えないこと

| 項目 | cascade_v3 | 今回（cascade_v4_camera） |
|---|---|---|
| 入力 | 正しい位置と向き＋雑音 | 真上のカメラ（overhead_a）の深度と物体ごとの切り分けから、走行と同じ処理（`Executive.look`）で作った見立て |
| 教師 | 箱を一つ外へ移し、1.5 秒後にほかの箱が動いたか | 同じ |
| 場面と区分 | 番号 2000〜2399、train／seen／unseen（unseen は 2000〜2120） | 同じ |
| 合格の条件 | seen と unseen のそれぞれで、AUC が規則より 0.10 以上高く、Brier スコアが規則以下 | 同じ。規則の値も、同じカメラの見立てから計算する |

作り方：`scripts/gen_cascade_data.py --input camera --split <区分>`、出力は `artifacts/cascade_v4_camera/`。

## 限り

- 物体ごとの切り分けは、シミュレーターが出したもの。実機では、カメラの画像から推定する部分にあたる。
- 見るのは真上の固定カメラ一つ。横からの見直し（走行ではガントリーを動かして見る）は入れない。
- カメラに写らない箱は、見立てに入らないので、特徴も教師も作られない。
- 教師は、箱を瞬時に外へ移したときの崩れであり、吸着で持ち上げる動作そのものではない。
- 運ぶ経路は学習しない。

## 提出への入れ方

- 期限までに、データ・学習・上の判定まで終わり、合格した場合に限り、「内蔵カメラの見立てから学んだ崩れの予測」と書く。
- この予測を使った走行は、今回の計画に入れない。走らせなかった場合は、走行で効くかは「未確認」と書く。
- 期限までに判定まで終わらなければ、提出には入れない。その場合、既存の予測（cascade_v3）とカメラの見立ての開発は別のものとして書き、「内蔵カメラから学習した最適モデル」とは書かない。
