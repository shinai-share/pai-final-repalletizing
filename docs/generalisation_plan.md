# 崩れ方が変わっても通用するかの確かめ方（2026-10-31、走らせる前に固定）

目的：特定の荷崩れに合わせるのではなく、さまざまな崩れ方に適応できること（2026-10-31 の方針）。
学習するのは「箱を一つ抜いたとき、ほかのどの箱が崩れるか」の予測です。ロボットは、この予測と見立てから、取る順番と見に行く場所を決めます。

この文書は、学習データも走行もまだ作っていない時点で書きました。結果を見た後に、条件・基準・番号を変えません。
走行に使う番号は、下の規則で場面の中身（段の数・品目・ブレーキ）だけを見て選びました。ロボットを動かした結果は見ていません。

## 崩れ方の場面（`shinai_pi/scenarios.py`）

番号ごとに、次を乱数で決めます。

| 項目 | 範囲 |
|---|---|
| 段の数 | 2・3・4 |
| 品目 | 設定にある 2 品目（BEV-500x24、CTN-M） |
| ブレーキ | 3.5〜9.0 m/s²（これまでの 3.5〜7.0 を、崩れの大きい側へ広げた） |
| ラップの外れた段 | 上から 1 段〜全段 |
| 摩擦・箱ごとの重さと重心・横揺れ・路面の段差 | これまでと同じ範囲 |

## 学習に使わない条件

| 区分 | 中身 | 使い方 |
|---|---|---|
| train | 3 段でなく、ブレーキ 8.0 以下で、番号が 5 の倍数でない | 学習 |
| seen | 学習と同じ条件で、番号が 5 の倍数 | 学習と同じ条件での評価 |
| unseen | 3 段、またはブレーキ 8.0 超 | 学習に入れていない条件での評価（適応の確かめ） |

## データ

- 学習：番号 2000〜2399 の train（184 個の荷）
- 評価：番号 2000〜2399 の seen（37 個）と unseen（179 個のうち番号の小さい 60 個）
- 一つの荷から、抜く箱を最大 MAX_REMOVALS 個選び、抜いた後に物理で崩れたかを記録する（`scripts/gen_cascade_data.py --split`）

## 予測の合格の条件

seen と unseen のそれぞれで、次の二つを満たすこと。

1. 学習した予測の AUC が、幾何の規則の AUC より 0.10 以上高い
2. 学習した予測の Brier スコアが、幾何の規則以下

片方でも満たさなければ不合格として残し、走行には使いません（幾何の規則のまま走らせ、その事実を書きます）。

## 走行

機体は 2026-10-31 の直しの版です。

- 爪は、板の −y 面にボルトで留めた台座の案内を通る形です。
- 爪は、A の上で持ち上げた直後に入れます。
- 手首には向きの制限があり、工具の上げる上限は 0.0 です。

方式は `shinai_learned`（予測が合格した場合）、または `shinai`（不合格の場合）です。`run_mission.py --scenarios --record --trace` で走らせます。

| 順 | 番号 | 区分 | 中身 | 選び方 |
|---|---|---|---|---|
| 1 | 3001 | unseen | 3 段・BEV-500x24・ブレーキ 7.46 | 3000 以上で最初の unseen の 3 段 |
| 2 | 3014 | unseen | 2 段・BEV-500x24・ブレーキ 9.00 | 3000 以上で最初の unseen の 2 段・ブレーキ 8.0 超 |
| 3 | 3000 | seen | 2 段・CTN-M・ブレーキ 4.57 | 3000 以上で最初の seen の 2 段 |
| 4 | 3025 | seen | 2 段・BEV-500x24・ブレーキ 4.97 | 3000 以上で 2 番目の seen の 2 段 |

判定は、`scripts/stage_gate.py S3` の中身（落下なし・配置の検証に落ちた箱なし・二次の荷崩れなし・終わり方が確認済み・置いた箱がすべて基準内・作業中に作業場の外へ出た箱なし）で行います。
3 段の荷は、段階 S3 の箱の数（6〜24）を超えます。それでも、判定の中身は変えずに同じ関数で判定します。

期限までに走らせ終えられなかった番号は「未実施」と書きます。番号を入れ替えたり足したりしません。

## 追記：この学習が示すもの・示さないもの（2026-10-31 夜）

この追記は、学習データの生成を始めた後、生成の結果・学習・走行のどれも見ていない時点で書きました。
上の条件・基準・番号は変えていません。足したのは、記録の項目と、比べるための走行だけです。

### 学習データの中身

| 項目 | 中身 |
|---|---|
| 入力 | シミュレーターが持つ箱の正しい位置と向きに、雑音を足したもの（位置 1 cm・向き 1.5 度）。内蔵カメラの映像から作ったものではない |
| 教師 | 箱を一つ作業場の外へ瞬時に移し、1.5 秒の物理の後に、ほかの箱が動いたかどうか。吸着で持ち上げる動作そのものではない |
| 予測するもの | 支えを取り除いたときに、どの箱が崩れるか |

この学習が示せるのは、次のことに限ります。

- 支えを取り除いたときの崩れを、幾何の規則より正しく予測できるか
- その予測が、学習に入れていない崩れ方（3 段・強いブレーキ）でも保たれるか

次のことは示しません。

- 内蔵カメラの映像から、荷の形を学習して認識すること
- 運ぶ経路を学習すること（経路は、学習ではなく幾何の計画で決めています）

### 走行のときの、カメラと学習の関係

- 走行では、ロボットは内蔵カメラの深度と物体ごとの切り分けから、箱の位置と向きを推定します。予測は、この推定の上で使います。
- 物体ごとの切り分けは、シミュレーターが出したものです。実機では、カメラの画像から推定する部分にあたります。
- 学習の入力（正しい位置＋雑音）と、走行の入力（カメラからの推定）は、作り方が違います。この差が走行の結果に効く可能性があります。

### 走行の追加：同じ番号で規則だけの走行と比べる

学習した予測が判断を変えたか、規則より良くしたかを確かめるため、次を足します。

1. `shinai_learned` で走らせるときは、箱を選ぶたびに、同じ見立てから規則だけなら選んだ箱を記録する（`PICK_PLANNED` の `rule_choice`・`rule_risk`・`model_changed_choice`、`result.json` の `learned_decisions`・`learned_changed`）。
2. 予測が合格した場合、表の番号ごとに `shinai_learned` の直後に `shinai` を走らせる。順は 3001 学習 → 3001 規則 → 3014 学習 → 3014 規則 → 3000 → 3025 の順で同じように続ける。
3. 予測が不合格の場合は、`shinai` だけを走らせる（上の規定どおり）。

比べ方は、走らせる前に次のとおり決めます。

- 番号ごとに、S3 の判定・二次の荷崩れの数・動いた箱の数・落下・かかった時間を並べて書く。
- 「規則より良くした」と書くのは、次をすべて満たすときに限る。
  - 一組以上で、学習の側の二次の荷崩れと動いた箱の合計が少ない。
  - 学習の側が多い組がない。
  - 学習の側だけが S3 に落ちた組がない。
- 組の数は 4 以下です。統計の差としては書きません。
- `learned_changed` がどの走行でも 0 のときは、「予測は判断を変えなかった」と書く。
- 走らせ終えられなかった走行は「未実施」と書く。
